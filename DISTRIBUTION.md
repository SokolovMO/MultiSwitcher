# Самостоятельный выпуск MultiSwitcher

Раздача: https://sokolovmo.ru/multiswitcher/ (Vyrex).
Apple Developer, нотарификация, GitHub App, Vercel и панель публикации не нужны.
ZIP и appcast подписаны Ed25519; Sparkle встроен в приложение. Запросы обновлений
идут по HTTPS непосредственно на наш сайт, без текста, профиля и содержимого буфера.
Сборка не включает Sentry. Единственный канал обновлений — обычные выпуски.

## Выпуск

1. Повысить CFBundleVersion в macos/Info.plist для каждой сборки; при необходимости
   обновить CFBundleShortVersionString. Не заменять опубликованный ZIP тем же build.
2. Выполнить core, selection, interaction и release проверки; проверить физический ввод.
3. На Apple Silicon Mac с Xcode и Python 3:

```sh
bash scripts/prepare_sparkle.sh
bash scripts/prepare_dmg.sh
python3 scripts/build_release.py --output /tmp/multiswitcher-build-N
python3 scripts/publish_release.py /tmp/multiswitcher-build-N
```

Выходная папка должна быть новой и пустой. Подписи ZIP/appcast проверяются перед
публикацией. Исходники архивируются из фактического текущего дерева, включая
незакоммиченные изменения. Приватные ключи в раздачу и исходники не включаются.
Скрипт публикации переключает current атомарно и сохраняет прежние архивы.
Ни перезапуска nginx, ни изменения proxy для последующих выпусков не нужно.

## Подпись и первый запуск

Используется существующий локальный сертификат MultiSwitcher Stable Code Signing.
Это не Apple Developer ID; платный аккаунт не требуется. Не менять сертификат без
миграции: он участвует в идентичности приложения для разрешений macOS. Сборщик
проверяет соответствие требованию подписи установленной копии, если она есть.
Для CI без доступного сертификата можно собирать с MULTISWITCHER_SIGN_IDENTITY=-;
публичный выпуск по умолчанию использует постоянный сертификат. Самопроизвольного
перехода на ad-hoc при недоступности сертификата нет.

Отдельный постоянный Ed25519 seed:
~/Library/Application Support/MultiReleases/Signing/MultiSwitcher.seed.
Нужны защищённые резервные копии seed и ключа локального сертификата. Сборщик не
генерирует и не заменяет их автоматически. --seed переопределяет путь.

ZIP устанавливается вручную с разрешением первого запуска в настройках macOS.
Готовый install.sh проверяет HTTPS-загрузку, SHA256, размер и структуру архива,
bundle ID/build, подпись кода, updater key/URL и selftest. Снимает карантин только
с проверенной копии, сохраняет прежнее приложение и не убивает незавершённую замену
текста. --verify-only проверяет раздачу без записи в /Applications.
Начальное доверие — к HTTPS-сайту/скрипту; SHA256 с того же сайта не заменяет
независимую подпись издателя. Дальнейшие обновления Sparkle требуют Ed25519.

## У пользователей

### Homebrew

```sh
brew tap SokolovMO/apps
HOMEBREW_MULTI_APPS_ALLOW_UNNOTARIZED=1 brew install --cask SokolovMO/apps/multiswitcher
```

Tap: https://github.com/SokolovMO/homebrew-apps . Явный параметр разрешает проверку
подписи и снятие карантина только с MultiSwitcher. Без него сохраняется стандартная
проверка Homebrew/macOS. Старый `--no-quarantine` удалён в Homebrew 7.
Для побайтово совпадающей установленной копии добавить `--adopt`, без `--force`.
Для нативного окна обновления использовать «Проверить обновления» в приложении.
Альтернатива после завершения работы и выхода из приложения:

```sh
brew update
HOMEBREW_MULTI_APPS_ALLOW_UNNOTARIZED=1 brew upgrade --cask SokolovMO/apps/multiswitcher
```

После каждого публичного build обновить tap: `python3 scripts/update_casks.py`
из homebrew-apps (локальный исходник — `homebrew-tap/`), проверить diff и опубликовать.
Обычная публикация приложения не обновляет tap. `auto_updates true` сохраняет
плановые обновления через Sparkle; явно названный cask обновляется и через brew.

«Проверить обновления» доступно в меню и в «Настройки → О приложении»; там же
можно отключить автоматические проверки. Установка требует подтверждения.
Перед перезапуском останавливается мониторинг клавиатуры, завершаются отложенные
замены и восстанавливается принадлежащий приложению буфер обмена. Профиль остаётся
в ~/Library/Application Support/MultiSwitcher и при обновлении не перезаписывается.
Разрешениями управляет macOS; если доступ сброшен, пользователь выдаёт его вручную.

## Хостинг и возврат

Существующий nginx обслуживает /multiswitcher/ из /var/www/multiswitcher/current/.
Публикации: /var/www/multiswitcher/releases/. previous указывает на прежний выпуск.
Возврат — атомарное переключение current на previous без reload nginx. Уже
установленным клиентам исправление выпускается с большим build, без автопонижения.

macOS 15+, только Apple Silicon. Проверка полной установки, профиля, разрешений,
реального обновления A → B, клавиатуры и буфера обмена остаётся отдельной приёмкой;
компиляция и модульные тесты её не заменяют.

## Разрешение для локального Sparkle

Владелец явно одобрил 2026-11-06 отключение только library validation для этой
схемы выпуска. Hardened runtime остаётся включён. Самостоятельный сборщик задаёт
MULTISWITCHER_INDEPENDENT_DISTRIBUTION=1 и использует отдельный
macos/MultiSwitcher-independent.entitlements с
com.apple.security.cs.disable-library-validation=true. Это разрешает загрузку
библиотек без проверки Apple Team ID. Локальная подпись приложения и Ed25519
проверка обновлений сохраняются. Обычные сборки используют прежние entitlements.

## Меню в строке состояния

В приложении используется только NSStatusItem.menu / NSMenu. Прежний custom
NSPopover и его renderer перемещены в legacy-ui вне target приложения. Режимы
проверки тоже открывают только NSMenu. scripts/check_layout_state.sh проверяет
настоящий контроллер и 100 циклов состояния на изолированном профиле; ему можно
передать путь к собранному .app, чтобы проверить именно релизный бинарник.

## DMG

Основная загрузка сайта — оформленный DMG с приложением и ссылкой на /Applications.
Пользователь перетаскивает приложение в «Программы»; Finder спрашивает о замене
прежней копии. ZIP остаётся архивом для Sparkle и запасной загрузкой. Сборщик
проверяет монтирование DMG, вложенное приложение и selftest, затем подписывает DMG
ключом Ed25519. Публикация проверяет подпись и SHA256. Инструменты dmgbuild из
requirements-release.lock устанавливаются только в .build/release-tools и не
включаются в приложение. Сам DMG не запускает установку автоматически.
