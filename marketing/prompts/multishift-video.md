## суть продукта

сначала прочитай актуальные `AGENTS.md`, `README.md`, код приложения и локальные инструкции. сведения ниже — проверенный ориентир, но проверь их в текущем коде и интерфейсе:

- multishift обрабатывает файлы из finder: человек начинает перетаскивание, нажимает shift или настроенную клавишу, выбирает действие в круговом меню и отпускает файл.
- для изображений есть преобразование форматов, включая webp. конкретный набор действий зависит от входного формата.
- результат публикуется как отдельная копия, исходный файл остаётся на месте; существующие результаты не должны перезаписываться.
- обработка локальная, без обязательного аккаунта и облачной загрузки файлов. проверка обновлений — отдельная сетевая функция.
- интерфейс — swiftui/appkit с системной типографикой macos. в части небольших меток применяется системный rounded-шрифт.

полезные точки входа для проверки: `macos/Sources/AppDelegate.swift`, `NativeModels.swift` (в том числе `actions(for:mode:)`), `NativeViews.swift`, `NativeFileEditor.swift`, `DesignSystem.swift`, `MultiDesignKit.swift`, `Core/WheelGeometry.swift`, `Core/FileJobCoordinator.swift`.

главная бизнес-ценность: «другой формат — прямо из finder. оригинал остаётся». человек получает нужную копию, не открывая отдельный редактор ради одной операции. не обещай поддержку любого формата, одинаковое время обработки для любых файлов или выдуманный процент сжатия.

выбери один основной сценарий: `photo.png` → круговое меню → `webp` → готовая копия рядом с оригиналом. используй синтетическое изображение и вымышленное имя файла, без частных документов. если этот путь в установленной сборке устроен иначе, воспроизведи реальный путь; не сокращай его выдуманными кнопками.

сверь установленное приложение и исходники: путь, версия, runtime macos, реально открытый экран. получи настоящие снимки/запись приложения, строки меню, кругового меню и результата, когда они доступны. запускай только одну обычную копию приложения. для технических fixture-режимов используй изолированное состояние; не меняй пользовательские настройки и файлы ради красивого кадра.

не меняй нативное приложение ради видео и не выпускай обновление приложения. сохраняй оригинальную иконку multishift; если на каком-либо материале есть запрещённые прописные надписи, кадрируй или переверстай только этот фрагмент внутри монтажной композиции, не меняя глобальные ресурсы приложения.

## жёсткие правила оформления

1. абсолютно весь экранный текст только строчными буквами: `multishift`, `shift`, `finder`, `mac`, `webp`, `photo.png`, `photo.webp`, `sokolovmo/multishift`. это относится и к запечённому тексту в скриншотах. проверь картинки глазами, одного css text-transform недостаточно.
2. никаких сторонних веб-шрифтов, fontshare, satoshi, inter и сетевых загрузок шрифтов. используй системный стек macos: `-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", sans-serif`. внутри реального ui оставь те системные варианты, которые применяет приложение. не подменяй шрифт исходного интерфейса. финальный рендер выполняй на macos для корректной системной типографики.
3. чистый минимализм: светлый нейтральный фон, почти чёрный текст, смысловые системные акценты только в реальном ui. без декоративных градиентов, стеклянных карточек, 3d-поворотов интерфейса, конфетти и шаблонных блоков с иконками.
4. одна главная вещь в каждом кадре. интерфейс показывай крупно, подписи должны читаться на телефоне при просмотре горизонтального ролика. сохраняй безопасные поля; не накладывай заголовки на файл, меню или результат.

## темп и анимация

основная версия — 10 секунд, 1920 × 1080, 60 fps, 600 кадров. продление до 12 секунд допустимо только если реальный путь иначе не читается. не растягивай ролик паузами, длинными проявлениями и академичными пояснениями.

нужны резкие смены планов, короткие приближения, нажатие клавиши, подхват и отпускание файла, быстрое пружинистое появление меню. ориентир для spring: stiffness 600–900, damping 15–22, mass 0.35–0.6, движение 10–16 кадров. настраивай по кадрам, а не слепо копируй числа.

приоритет движению, которое объясняет действие: файл захватывается → появляется меню → выбирается реальное действие → возникает результат. лишнее движение убирай. не двигай всё одновременно. курсор должен достичь цели до звука щелчка; файл должен оставаться связанным с курсором во время перетаскивания. не приписывай приложению реальную скорость обработки по ускоренной монтажной сцене.

вся анимация — детерминированная функция кадра через `useCurrentFrame`, `spring`, `interpolate`; без css animation, таймеров, `Date.now` и незасеянной случайности. перемотка и повторный рендер обязаны давать тот же результат.

если показываешь набор имени файла, добавь мигающую каретку, неравномерные интервалы и микропаузу, а не равномерную побуквенную выдачу. никаких клавиатурных звуков без видимого нажатия или появления буквы.

## предложенная раскадровка на 10 секунд

это план по смыслу, а не разрешение выдумывать интерфейс. после осмотра реального приложения адаптируй точный маршрут:

- **0.0–1.2 с:** настоящий или точно восстановленный finder, выбран `photo.png`. короткий титр: «нужен другой формат?».
- **1.2–2.4 с:** файл подхватывается курсором; крупный тактильный нажим `⇧ shift`, возникает настоящее круговое меню.
- **2.4–4.2 с:** курсор проводит файл по реальному пути к `webp`, есть ясное выделение цели и отпускание. если сначала нужен дополнительный выбор — покажи его, не вырезая причинно-следственную связь.
- **4.2–6.0 с:** подтверждённое завершение операции и готовый `photo.webp`. используй реальное отображение результата: finder, история или системное уведомление — только то, что действительно существует в этой сборке.
- **6.0–8.0 с:** рядом видны исходный `photo.png` и новый `photo.webp`. титр: «копия готова. оригинал на месте.» никаких выдуманных размеров файлов и процентов экономии.
- **8.0–10.0 с:** настоящая иконка, `multishift`, короткий финал «перетащи. обработай копию.», адрес `sokolovmo/multishift`. можно добавить «на твоём mac», если это остаётся читаемым.

не используй универсальный круг из случайных форматов вместо реального меню. проверь фактические сектора, положение webp, дополнительные окна и действие после drop. не делай постановочный progress-bar, который выглядит как замер реальной скорости.

## саунд-дизайн — только реальные записи

сначала проверь репозиторий на исходные звуки. если подходящих нет, возьми проверенные записи из локальной библиотеки или открытые записи с понятной лицензией. для этого семейства роликов клавиатура должна быть **ножничной, низкопрофильной**, не механической и не butterfly. описание устройства у автора должно это подтверждать; слово «macbook» само по себе недостаточно.

уже одобренный источник: plummet, «intense typing on a laptop macbook keyboard», cc0, автор прямо пишет о scissors low profile keyboard:
https://freesound.org/people/Plummet/sounds/749425/

проверь актуальную лицензию и используй сохранённые в multiswitcher сэмплы или скачай исходник. фоли на shift можно взять из той же ножничной записи; не выдавай произвольную клавишу за документальную запись конкретного shift.

нужны короткие физические клики захвата/отпускания, акцент shift, лёгкий записанный свуш при появлении меню и аккуратный акцент готового результата. звук должен следовать действию, а не заполнять каждую паузу. без тяжёлого киношного баса на каждом переходе, случайных мелодий и музыки по умолчанию. озвучка не нужна.

не синтезируй «реальные» клавиши осцилляторами и не используй forge-банк как запись. uisfx тоже не нужен для этой версии. разные нажатия бери из разных физических дублей, с небольшой вариацией уровня; повторяемый звуковой язык допустим для одних и тех же действий.

создай единую таблицу кадров для визуальных событий и аудио. атака клика/клавиши — на кадре контакта; пик свуша — на кадре появления/смены плана. учитывай измеренный преролл записи. обрезки должны сохранять атаку и отпускание без щелчка на границе.

сведи отдельный wav-мастер 48 кгц/24 бит и подключи его в remotion ровно один раз. сохрани cue sheet, ссылки, авторов, лицензии и описание обработки. музыку и голос, если они неожиданно есть в исходном пользовательском материале, не удаляй без указания; здесь исходно планируется только sfx.

проверь результат через real-sfx и earshot: отсутствие клиппинга, true peak, слышимость акцентов по измерениям, моносовместимость и совпадение атак с кадрами. для коротких клавиш и кликов цель — не больше одного кадра при 60 fps; непрерывные свуши проверяй по пику, не путай их начало с ошибкой синхронизации. приводи реальные числа, не обещай «идеально» только по исходному коду. не утверждай, что прослушал звук человеческими ушами. если семантические модели недоступны, честно укажи режим измерительной проверки. не загружай аудио в стороннюю llm без явного согласия.
