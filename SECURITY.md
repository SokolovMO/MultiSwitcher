# Security policy

## Reporting a vulnerability

Do not publish exploitable issues, exploit steps, credentials, or sensitive user data in a public GitHub issue.

If private vulnerability reporting is enabled, use the Report a vulnerability action on the repository Security page:
https://github.com/SokolovMO/MultiSwitcher/security

If that option is unavailable, contact the repository owner through the GitHub profile and first ask for a private reporting channel. Do not include exploit details or user data in the initial public message.

MultiSwitcher processes keyboard events and can modify text in other applications. A useful report includes the app version/build, macOS version and architecture, affected feature, a minimal synthetic reproduction, and whether the app came from the official download page at https://sokolovmo.ru/multiswitcher/.

Do not send passwords, private text, clipboard contents, profiles, private keys, or raw diagnostic logs. MultiSwitcher does not upload them automatically.

## Supported versions

Report issues against the latest build available from the official download page. Release validation records describe what was checked and what remains unverified. The current independent distribution is not Apple-notarized; there is no long-term security support commitment for older builds.

## Response expectations

There is no published response-time guarantee. The maintainer will assess reports and distribute fixes through reviewed changes and signed releases when available.
